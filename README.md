# YouTube 日本ランキング（動画 / ライブ・完全無料）

日本で人気の YouTube を、**動画**（ショート除外）と**ライブ配信**に分けてランキングにするサイトです。2時間ごとに自動で更新されます。

| 区分 | タブ | 内容 |
|---|---|---|
| 動画 | 急上昇 | 投稿72時間以内の動画を、直近4時間の再生ペース（新しさで補正）で順位付け |
| 動画 | デイリー / ウィークリー | 直近24時間 / 7日間の再生数の増加量順 |
| ライブ | 配信中 | 集計時点で配信中のライブを同時視聴者数順 |
| ライブ | 急上昇 / デイリー / ウィークリー | 配信アーカイブを動画と同じ基準で集計 |

URLの末尾で表示を指定できます（例: `#live/now`, `#video/daily`）。

## 費用が0円の理由

| 部分 | 使うもの | 費用 |
|---|---|---|
| データ取得 | YouTube Data API v3 の無料枠 | 0円（有料プランが存在せず、上限に達するとその日は止まるだけ） |
| 定期実行 | GitHub Actions（公開リポジトリの標準ランナーは無料） | 0円 |
| 公開 | GitHub Pages（公開リポジトリは無料） | 0円 |

Google Cloud プロジェクトの課金（請求先アカウント）は無効にしてあります。

### YouTube API の無料枠の使い方（1日12回実行）

2026年6月から、YouTube API の上限はメソッドごとの「バケット」に分かれています。

| バケット | 1日の上限 | このツールの使用量（目安） |
|---|---|---|
| 通常（videos.list / channels.list / playlistItems.list など） | 10,000ユニット | 1回 最大750 → 1日 最大9,000 |
| search.list | 100回 | 1回 6回 → 1日 72回 |
| videos.batchGetStats（再生数の取得） | 10,000ユニット | 1回 数十〜160 |

手動実行を何度もすると search.list の100回を超えることがあります（超えた分はその日スキップされるだけです）。

## セットアップ（済み）
1. Google Cloud でプロジェクトを作り、YouTube Data API v3 を有効化 → APIキーを作成（YouTube Data API v3 のみに制限）
2. このリポジトリの **Settings → Secrets and variables → Actions** に `YT_API_KEY` を登録
3. **Settings → Pages → Source** を **GitHub Actions** にする
4. **Actions → update-ranking → Run workflow** で手動実行（以降は2時間ごとに自動）

## 最初の数日について
- 再生数の推移はこのツールが自分で記録しています。デイリーが正確になるのは記録を始めて24時間後、ウィークリーは7日後からです。それまでは推定値（「推定」と表示）です。
- 追跡するチャンネルは、使うほど増えていきます。人気の動画や配信が見つかるとそのチャンネルを覚えて、以降は新着を毎回チェックします。

## 仕組み
1. 候補集め
   - 公式の `mostPopular`（日本）：音楽・映画・ゲーム
   - 検索：配信中のライブ、直近48時間で再生数の多い4分以上の動画、カテゴリ別（毎回3カテゴリずつ巡回）
   - 覚えたチャンネルの新着：勢いのある順＋残りを巡回で最大400件
2. 選別
   - 日本語の動画か：音声言語・タイトルのかな・チャンネルの国で判定
   - ショートを除外：60秒以下は除外。61〜180秒は `youtube.com/shorts/ID` に問い合わせて判定（クォータを使わない）
   - 動画かライブか：配信中・配信予定の時点で見かけたものは「長さ0＝本物のライブ」「長さあり＝プレミア公開（動画扱い）」で判定。見かけていないものは「ライブの記録があり10分以上」をライブとして扱う
3. 追跡中の全動画の再生数を記録して、伸びからランキングを計算 → `site/data/ranking.json`

## 調整したいとき
`collector/collect.py` の先頭にある `CFG`：

- `trend_max_age_h`: 急上昇の対象にする投稿の新しさ（初期値72時間）
- `trend_window_h`: 急上昇の速度を測る時間（初期値4時間）
- `channel_poll_per_run`: 1回で新着をチェックするチャンネル数（1件あたり1ユニット）
- `search_calls_per_run`: 1回で使う search.list の回数
- `live_min_duration_s`: ライブ扱いにする最短の長さ

## ローカルでテスト（APIキーなし）
```
YT_MOCK=1 python3 collector/collect.py
cd site && python3 -m http.server
```
`tools/mock_api.py` の架空データで動きます。

## 注意
- YouTube公式のランキングではありません（ページ下部にも表記しています）。
- YouTube API サービス利用規約に従い、取得したデータは8日以内に古いものから削除しています。
